# 词库表脚本初始化方案

1. **初始化 DDL 脚本**：建立符合您架构文档的表结构，并补充了之前建议的去重字段。
2. **智能分级逻辑脚本**：这是一套基于 SQL 的逻辑，用于将 15,000 个单词自动划分为“谜题库（Answers）”和“猜测库（Guesses）”。



### 1. 初始化数据库结构 (DDL)



这段脚本将创建 `allowed_words` 表，并添加为了实现“每日不重复”逻辑所需的 `last_used_at` 字段。

SQL

```sql
-- -----------------------------------------------------
-- 1. 创建允许猜测的词库表 (allowed_words)
-- -----------------------------------------------------
CREATE TABLE IF NOT EXISTS allowed_words (
    word VARCHAR(5) PRIMARY KEY,
    language VARCHAR(10) NOT NULL DEFAULT 'en',
    
    -- 核心标记：TRUE=可以做谜题答案(约3000个), FALSE=仅能作为猜测词(约12000个)
    -- 对应文档中的 is_daily_answer
    is_daily_answer BOOLEAN NOT NULL DEFAULT FALSE, 
    
    -- 流行度分数：用于后续难度分级 (0.00 - 100.00)
    -- 对应文档中的 popularity_score
    popularity_score NUMERIC(5, 2) DEFAULT 0.00,
    
    -- 新增建议字段：用于追踪该词上次被选为谜题的时间，防止短期重复
    last_used_at TIMESTAMP NULL
);

-- -----------------------------------------------------
-- 2. 创建索引 (性能优化)
-- -----------------------------------------------------
-- 优化 n8n 的查询速度：快速筛选出“可以做答案”且“很久没用过”的词
CREATE INDEX idx_candidate_selection 
ON allowed_words (language, is_daily_answer, last_used_at);

-- -----------------------------------------------------
-- 3. (可选) 创建每日谜题表 (daily_puzzles) 
-- 确保符合文档中的复合唯一索引要求
-- -----------------------------------------------------
CREATE TABLE IF NOT EXISTS daily_puzzles (
    id SERIAL PRIMARY KEY,
    date DATE NOT NULL,
    game_type VARCHAR(50) NOT NULL, -- 'octordle', 'wordle'
    language VARCHAR(10) NOT NULL DEFAULT 'en',
    answers TEXT[] NOT NULL,        -- 存储每日的8个词
    metadata JSONB NOT NULL DEFAULT '{}',
    created_by VARCHAR(50) DEFAULT 'AI',
    created_at TIMESTAMP DEFAULT NOW()
);

-- 防止同一天、同一类型生成重复数据
--
CREATE UNIQUE INDEX idx_daily_unique_puzzle 
ON daily_puzzles (date, game_type, language);
```

### 2. `is_daily_answer` 字段的更新逻辑



您有 15,000 个单词，如果手动标记会累死人。最科学的方法是**引入外部词频数据**来批量更新。



#### 逻辑思路：



1. 创建一个临时表，导入包含单词频率（Frequency）的数据（网上有很多开源的 English Word Frequency CSV）。
2. 计算频率排名前 20%~25% 的单词（约 3000-3500 个）。
3. 将这部分单词的 `is_daily_answer` 设为 `TRUE`，其余设为 `FALSE`。
4. 同时计算归一化的 `popularity_score`。



#### 操作脚本 (SQL Workflow)：



假设您找到了一份 CSV 数据，包含两列：`word` 和 `frequency_count`。

SQL

```sql
-- A. 创建临时表用于导入频率数据
CREATE TEMP TABLE temp_word_frequency (
    word VARCHAR(5),
    freq_count BIGINT
);

-- B. 模拟导入数据 (在实际操作中，使用 \COPY 命令或 Navicat 导入 CSV)
-- \COPY temp_word_frequency(word, freq_count) FROM 'frequency_list.csv' DELIMITER ',' CSV HEADER;

-- C. 核心更新逻辑：
-- 此脚本会自动根据频率高低，划分 "Answer" 和 "Guess"
WITH ranked_words AS (
    SELECT 
        word,
        freq_count,
        -- 根据频率排名 (1 = 频率最高)
        ROW_NUMBER() OVER (ORDER BY freq_count DESC) as rank_position,
        -- 计算总数
        COUNT(*) OVER () as total_count
    FROM 
        temp_word_frequency
    WHERE LENGTH(word) = 5 -- 再次确保只处理5字母词
)
UPDATE allowed_words aw
SET 
    -- 1. 更新是否为答案：只有排名前 3500 的词才配做“谜题”
    is_daily_answer = (rw.rank_position <= 3500),
    
    -- 2. 更新流行度分数：将排名归一化为 0-100 的分数
    -- 排名第一的分数接近 100，排名最后的接近 0
    popularity_score = ROUND(
        CAST(100.0 * (1.0 - (rw.rank_position::NUMERIC / rw.total_count::NUMERIC)) AS NUMERIC), 
        2
    )
FROM 
    ranked_words rw
WHERE 
    aw.word = rw.word;

-- D. 清理生僻词标记 (可选)
-- 即使频率很高，如果是敏感词或不适合的词，手动修正
-- (这部分通常由您的 n8n Agent 在运行时做，但数据库层面可以先硬编码几个黑名单)
UPDATE allowed_words 
SET is_daily_answer = FALSE 
WHERE word IN ('MERDE', 'FECAL', 'SLUTTY'); -- 示例黑名单
```



### 3. n8n 如何使用这个库？



配置好上述数据后，您的 n8n Agent 节点只需要运行下面这条 SQL 就能获得完美的候选词：

SQL

```sql
-- 获取 50 个候选词给 AI 挑选
SELECT word 
FROM allowed_words
WHERE 
    language = 'en' 
    AND is_daily_answer = TRUE  -- 只选常用词
    AND (last_used_at IS NULL OR last_used_at < NOW() - INTERVAL '60 days') -- 冷却期逻辑
ORDER BY RANDOM() -- 随机抽取
LIMIT 50;
```



### 💡 哪里找频率数据？



为了执行步骤 2，推荐使用 **Peter Norvig's Google Web Trillion Word Corpus** 的派生列表，或者 Kaggle 上的 **English Word Frequency** 数据集。只需要提取其中长度为 5 的单词即可。
